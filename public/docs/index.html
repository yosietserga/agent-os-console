01Arquitectura del Sistema

Next.js 16 con una única ruta visible (/) y un mini-service de streaming dedicado. Regla del entorno: un solo puerto expuesto (:3000 vía gateway); el mini-service se alcanza con ?XTransformPort=3003.

Decisiones estructurales

⚖️ Ruta única + gateway con XTransformPort

Solo / existe; las 3 vistas (Topología Viva · Kanban KPI · Consola) son tabs internos. REST siempre con rutas relativas; WebSocket siempre io("/?XTransformPort=3003") con path /.

🔬 El mini-service es readonly + inferencia

topology-engine lee la BD con bun:sqlite readonly (CommandLog, Finding, CycleRun, MemoryEntry, CostLedgerEntry) y ejecuta inferencias L2 reales. Nunca escribe — la observabilidad no muta lo observado.

🔌 LLM-agnóstico por diseño (P8)

Ningún controlador de negocio importa SDKs de proveedores: toda inferencia pasa por el L2 Control Plane (sanitización P12 → sandwich capa 3 → ledger inmutable de costos).

📁 Estructura de carpetas
src/app/            page.tsx (ruta única) · api/agent-os/* (6 routes)
src/components/     topology-live/ (canvas·panels·kanban) · agent-os/ (10 paneles)
src/lib/            agent-os/ (núcleo) · topology/ (escenario 22 nodos)
mini-services/      topology-engine/ (:3003 · engine·inference·db)
prisma/ · db/       schema · custom.db (SQLite)
scripts/            seed · sync · audits · mejorate-scan
⏱️ Presupuesto de gateway (AP-032): todo comando responde en <25s. Los pipelines largos corren en background con polling del frontend.

04Modelo de Datos

SQLite vía Prisma (db/custom.db) — 16 modelos, ledgers append-only (P9). Despliega cada grupo:

🏛️ Constitución y memoria (CardinalRule · CommandDef · MemoryEntry)

Las 15 reglas P1-P15 + W-CTA y los 18 comandos con metodología (semilla del boilerplate upstream). La memoria empírica es append-only: APs (anti-patrones con severidad), WINs (clases W1-W8), WORKLOG y REFERENCE.

📡 Observabilidad (CommandLog · CostLedgerEntry · Finding · CycleRun · Report · RadiografiaRun)

Las 4 fuentes de evidencia del sentinela + ledger de costos de cada inferencia (tokens · USD · latencia · outcome) + reportes époch inmutables. Finding.sourceRef es único → deduplicación natural.

🧬 Mejorate (ReferenceRepo · ScanRun · ExtractedPattern · AdoptionProposal)

Catálogo de 19 repos (1.2M★) con lastScannedAt — la columna que ata la síntesis al epoch: solo repos escaneados dentro del scan vigente son base honesta (AP-034). Las proposals guardan d1-d6, ΔS y veredicto del juez.

⚖️ Gobernanza (AdoptionProposal · PsimState · L2Model)

Snapshot PSIM con K1-K5 (metas: closure ≥0.90, half-life ≤2 iter…) y balance W1-W8; modelos L2 con estado de circuit breaker (CLOSED/OPEN/HALF_OPEN).

06Gobernanza PRE-v2.0 & L2

Tres roles inviolables: el Ejecutor implementa, el Optimizador (LLM) propone, el Juez (software determinista, sin LLM) decide.

📐 Puntuación constitucional: S = 100 × Σ(wi·Di) · Promoción inviolable: ΔS ≥ 5.0 ∧ ∀i ΔDi ≥ -2.0 ∧ (σcand + σbase) < |ΔS|

  • K4 Capability-Strengthening ≥ 1/iteración
  • K5 Gate Stability Streak (racha monótona)

07Mejorate — Auto-Improvement

Scan read-only de 19 repos de referencia (1.2M★) → extracción de patrones con L2 → adoptions evaluadas por el juez determinista. Copia y ejecuta: lee AGENTS.md, ejecuta: mejorate

AP-034 — la compuerta de honestidad (antes vs ahora)
flowchart TB
  subgraph ANTES["ANTES: fabricación silenciosa"]
    A1["scan 0/19 (403×19)"] --> A2["synthesize igual"] --> A3["epoch viejo + datos rancios"] --> A4["5 patrones 'extraídos' · exit 0"]
  end
  subgraph AHORA["AHORA: P2 Gate Honesty"]
    B1["pre-flight /rate_limit"] --> B2{"¿0 repos frescos?"}
    B2 -->|Sí| B3["ABORT antes de L2 · exit 1 · 0 tokens"]
    B2 -->|No| B4["solo repos del epoch · edad divulgada"]
  end
  
ANTES: 0/19 → synthesize sobre epoch viejo → exit 0 fabricado · AHORA: pre-flight → gate → abort honesto o síntesis fresca

Las 4 correcciones de raíz

  1. Token en call-time — la constante a nivel de módulo congelaba el valor al importar.
  2. Circuit breaker de cuota — sin token y remaining=0, omite llamadas destinadas a 403.
  3. Binding al epoch real — el epoch es el último scan (no el último COMPLETED); solo repos con lastScannedAt dentro del epoch; edad divulgada.
  4. Fallback honesto — las proposals derivan de los repos frescos del epoch (antes reciclaba patrones viejos → ΔS negativos del juez por duplicados).
🔑 Cuotas GitHub: anónimo = 60 req/h por IP compartida (cada run consume ~38 → 403 masivo). Con GITHUB_TOKEN en .env: 5.000 req/h — verificado 19/19 · 1.204.735★ · base epoch fresca.

## Contexto del Proyecto Instanciado (Protocolo 11)

### Misión
Proporcionar una herramienta profesional y segura que permita a los usuarios
combinar múltiples archivos de diferentes formatos en un único documento PDF…

### Goals del Proyecto
1. Procesar al menos 10 formatos de archivo diferentes
2. Combinar documentos en menos de 30 segundos para archivos de hasta 100MB
3. Mantener la calidad original de los documentos después de la fusión
4. Implementar cifrado de datos durante el procesamiento
5. Cumplir con regulaciones de privacidad de datos

### Personas del Dominio
| analyst → Analista de Documentos | operator → Operador de Procesamiento |
| executive → Gestor de Documentos Corporativos | apprentice → Usuario Novato |

### Reglas de Ejecución
1. Investigar exhaustivamente antes de asumir cualquier requerimiento técnico
2. Verificar la implementación tras cada cambio en el sistema
3. Memoria append-only (P9) · 4. Auto-crítica regular (P13) · 5. Iterar hasta los goals
API del instanciador (4 endpoints)
POST /api/agent-os/bootstrap { prompt } → { runId }
GET /api/agent-os/bootstrap historial (últimos 10)
GET /api/agent-os/bootstrap/[id] estado + spec + research + árbol · ?path= preview
GET /api/agent-os/bootstrap/[id]/download ZIP (solo COMPLETED, 409 si no)
Comportamiento ante fallos (P2 verificado en vivo): L2 caído → catálogo/persona con encabezado VERSIÓN DEGRADADA y nota en el pro-report; web_search sin resultados → síntesis sin citar fuentes; excepción del pipeline → status=ERROR visible en el UI; descarga anticipada → HTTP 409. Nada muere en el log sin procesar.
