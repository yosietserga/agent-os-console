P1Read-After-Edit Obligatorio
Tras editar, DEBE releerse la sección modificada (git diff o lectura directa) para verificar que el diff está presente y no ocurrió un no-op. Origen: AP-001 — 79 iteraciones con fallo oculto por no-op en regex.
P2Gate Honesty Absoluta
Prohibido declarar PASS sin ejecutar el comando real. Si no se ejecutó, declarar NOT RUN. Toda afirmación incluye comando + exit code + stdout. Origen: AP-004.
P3Closes-Finding Guard
NUNCA declarar resuelto un hallazgo si la solución reside solo en un mock. El archivo de producción debe contener la corrección sustantiva. Origen: AP-005.
P4Sync Atómica
Todo cambio en código DEBE commitearse junto con: especificaciones API (OpenAPI/Protobuf), documentación y memoria empírica (anti-patterns.md o wins-ledger.md).
P5Estilo Modo Claro Apple
Paleta inmutable: #ffffff bg, #f5f5f7 surface, #e5e5ea / #d2d2d7 borders, #1d1d1f / #86868b text, #0071e3 accent. Prohibido: mostaza, dark base, !important.
P6Layout Canónico 7 Posiciones
header · featuredContent · column_left · main · column_right · featuredFooter · footer. Prohibidos archivos monolíticos que ignoren el motor de layout.
P7Zero-Placeholder, Zero-Emoji
Datos comerciales DEBEN provenir de DB/config. Cero emojis en UI. Solo iconos SVG vectoriales. Origen: AP-007.
P8Aislamiento LLM-Agnóstico
Ningún controlador de negocio puede importar SDK de proveedor LLM. Toda inferencia pasa por L2 (envelope + circuit breaker + ledger). Cambiar proveedor = UPDATE en l2_model_registry. Compat: Claude, GPT, Gemini, DeepSeek, Qwen, Llama, Mistral, vLLM, Ollama, LM Studio.
P9Memoria Append-Only
anti-patterns.md, wins-ledger.md, worklog.md son append-only. Solo >>. Correcciones vía [CORRIGE-AP-XXX]. Único escribible: state.json (snapshot).
P10Entornos Dev/Deploy Declarados
.env define DEV_OS (windows) y DEPLOY_OS (ubuntu). .gitattributes fuerza eol=lf. Paths en código DEBEN usar path.join().
P11Onboarding Tour Obligatorio
Toda vista con >3 secciones interactivas, composer o >3 métricas DEBE montar OnboardingTour. WCAG 2.1 AA, focus-trap, persistencia, máximo 8 steps.
P12Anti-Prompt-Injection (7 capas)
1) structured prompts · 2) input sanitization · 3) system sandwich · 4) output validation · 5) HITL destructivas · 6) least privilege · 7) monitoring + audit. Origen: OWASP LLM Top 10 2026 LLM01.
P13Auto-Crítica Obligatoria
Modo A (self-revision, mín. 3 debilidades) · Modo D (adversario, 2 vectores si toca seguridad) · Tabla AGREE/DISAGREE (mín. 1 DISAGREE) · Análisis crítico contrario. Origen: Constitutional AI + AgentAuditor (arXiv Feb 2026).
P14Headless Browser Verification
Verificar "el server funciona" NO es HTTP 200. Browser headless (MCP browser-devtools) con 10 puntos: navigate + console + network + screenshot + WCAG + 7-pos + sticky + palette + Tour + CTA. curl/fetch SOLO para /health, /ping.
P15Expected-First Workflow
ANTES de implementar: generar docs/expected/<epoch>-<topic>.md con 6 secciones (wireframe, documental, comportamiento, rendimiento, accesibilidad, CAs verificables). DESPUÉS: expected-check → MATCH/BETTER/WORSE/FAIL.
W-CTAGlowingCtaButton
Botón primario al habilitarse (ej. 2+ archivos) DEBE usar GlowingCtaButton: gradient #0071e3 → #005bb5, glow pulsante 2.4s, 6 estados, prefers-reduced-motion desactiva glow, WCAG 2.1 AA, touch target ≥44px.

Circuit Breaker (L2 Control Plane)

Máquina de estados de 3 nodos que protege al sistema de cascadas de error del proveedor LLM. Vive en l2_app_routing_profiles.

CLOSED
Operación normal. Requests pasan al modelo primario.
OPEN
Bloqueado. R_fail ≥ 0.40 con N ≥ 10 muestras. Backoff activo.
HALF_OPEN
Canary tras T_reset_ms. OK → CLOSED. FAIL → OPEN.
Fórmula R_fail: Σ𝟙(eᵢ ∈ {5xx, 429, Timeout}) / N  ·  Backoff: T_sleep = min(T_max, random(T_base, T_prev × 3))

PRE-v2.0 Governance — 3 Roles

Separación estricta de roles para impedir que el LLM relaje su propia constitución. El juez es software determinista puro, sin LLM. Promoción requiere ΔS ≥ 5.0 ∧ sin regresiones severas ∧ significancia estadística.

ROL 1
Ejecutor
Code Agent
  • Permitido: escribir código siguiendo AGENTS.md
  • Prohibido: modificar archivos de reglas
  • Implementación: branch protection en GitHub
ROL 2
Optimizador
Rule Engineer
  • Permitido: abrir PRs a AGENTS.md desde pre/propose/*
  • Obligatorio: causa raíz + evidencia + diffs vs memory
  • Prohibido: mergear su propia propuesta
ROL 3
Juez Determinista
packages/eval — sin LLM
  • Permitido: ejecutar benchmark y emitir veredicto
  • Prohibido: contener cualquier LLM
  • Decisión matemática inviolable (CI pre-cycle.yml)
Condición de promoción: ΔS ≥ 5.0 ∧ ∀i ΔDᵢ ≥ −2.0 ∧ (σ_c + σ_b) < |ΔS|. Las 6 dimensiones: D1 Compilación (0.20) · D2 Contratos (0.15) · D3 Pipeline (0.20) · D4 Casos ocultos (0.20) · D5 Tokens (0.10) · D6 Arquitectura (0.15).

Paths Recíprocos — 5 Feedback Loops
  1. Memory Loop (entre sesiones): sesión N anexa AP/WIN → sesión N+1 lee en F0
  2. Gate Honesty Loop (en sesión): editar → releer P1 → diff OK? → continuar / reeditar (max 3) → escalar
  3. Circuit Breaker Loop (L2): CLOSED → OPEN → HALF_OPEN → CLOSED/OPEN(reset)
  4. PRE-v2.0 Loop: Ejecutor → Optimizador → Juez → PROMOTE → merge → WIN-XXX (W4)
  5. PSIM Loop: sesión N registra wins → sil trend → state.json → sesión N+1 lee KPIs
Paths Paralelos — 5 Patrones de Concurrencia
  1. Squad de Agentes en Worktrees — merges por blast radius: bajo → medio → alto
  2. MCP Servers Paralelos — 7 servers consumidos simultáneamente por el agente LLM
  3. Fase 0 Lecturas Paralelas — AGENTS.md, anti-patterns, worklog, state.json, 3 reportes
  4. Cierre de Sesión Escrituras Paralelas — append WIN + append AP + append worklog → reporte → state.json

3 Protocolos de Seguridad

Protocolos formales en docs/security/. Toda feature que toque datos externos o acciones destructivas DEBE pasar los tres.

PROTO · 1Anti-Prompt-Injection

7 capas defensivas contra OWASP LLM01 2026 (top 1 por 2ª edición consecutiva).

  1. Structured prompts <system>...<user_input>
  2. Input sanitization (decode-then-validate, typoglycemia norm)
  3. System prompt sandwich (antes Y después del input)
  4. Output validation (schema + exfiltration detection)
  5. HITL para acciones destructivas/externas
  6. Least privilege (sandbox FS, network allowlist, DB readonly)
  7. Comprehensive monitoring + audit log inmutable
